# Deep Learning Foundations

An approachable course in deep learning, built from concrete problems, intuition, and worked examples. Forty-two topics have notes and code companions.

Each topic has two matching notebooks:

- **Notes** follow a short story → labeled diagram → worked example flow, with plain-language explanations, practical uses, and limitations. Each lesson can be read independently.
- **Code** demonstrates those ideas in Python and PyTorch, with short explanations and locally generated or bundled datasets that run on CPU.

Every notebook includes a guided explanation of the problem being solved, why the method helps, and a small example worked through from inputs to outputs. The walkthroughs explain the purpose of each calculation and, where relevant, follow loss, gradients, and a parameter update. Hand-chosen teaching examples are distinguished from trained-model results. Code companions also connect these calculations to the actual Python operations.

Read the notes for understanding, then run an available companion to inspect the calculations and results. Notebook titles and headings are unnumbered so lessons can be shared independently. Available lessons are numbered consecutively in filenames and the table below. Planned topics remain unnumbered until added.

The two-notebook structure and teaching approach are inspired by [Machine Learning Foundations](https://github.com/avdhanda44/machine-learning-foundations). This is a separate project.

## Run locally

Use Python 3.9–3.12 for the pinned dependency set. Create an isolated environment in the repository directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m ipykernel install --prefix .venv --name deep-learning-foundations --display-name "Deep Learning Foundations"
python -m notebook
```

On Windows, create the environment with `py -m venv .venv` and activate it with `.venv\Scripts\activate`. Select the **Deep Learning Foundations** kernel, open a code notebook, and choose **Restart Kernel and Run All Cells**.

PyTorch, NumPy, and Matplotlib provide the computations and plots; scikit-learn supplies the bundled Iris and handwritten-digits datasets, data splitting, and the logistic-regression baselines; Notebook and ipykernel provide the notebook interface and kernel. Installing dependencies requires internet access. Running the notebooks needs no credentials, dataset downloads, GPU, or external services.

The first companion compares logistic regression on raw coordinates, logistic regression on a designed distance feature, and a small neural network on the same circular classification task. It keeps training, validation, and test examples separate and reports accuracy alongside decision-boundary plots. The Complete Training Loop fits a tiny regressor with separate training, validation, and test data. The intervening companions inspect fixed calculations and illustrative parameter changes rather than claim trained-model performance.

Random seeds are set in every code notebook. Saved outputs show a reference run where available; small numerical differences across platforms are possible. The notebooks teach through explanations and worked examples. Expanded notes include practice questions with answers, and code companions contain executable correctness checks.

## Verified reference run

The first eleven code companions were executed from separate fresh kernels on CPU using Python 3.9.6 and the pinned dependencies. Later companions were verified as described below. All verified code cells and embedded assertions passed.

For Why Deep Learning?, held-out accuracy was 52.1% for logistic regression on raw coordinates, 99.2% for the distance-feature model, and 99.2% for the neural network. The exact geometry rule reached 100%. The neural network learned a useful curved boundary, but matched a much simpler model given the right feature. This synthetic experiment demonstrates representation learning; it does not establish that deep learning is generally superior.

For Tensors and Forward Propagation, every code cell passed in a fresh CPU kernel. Explicit tensor calculations and `nn.Sequential` both produced scores of `1.900`, `2.175`, and `1.625`. Checks also confirmed correct bias broadcasting, agreement between batched and individual predictions, and unchanged parameters after forward passes.

For Loss Functions, all code cells passed in a fresh CPU kernel. Manual calculations matched PyTorch for MAE, MSE, Huber loss, binary cross-entropy, and multiclass cross-entropy. The temperature example produced MAE `2.000`, MSE `4.667`, and RMSE `2.160`; the extreme-logit examples remained finite.

For The Complete Training Loop, all code cells passed in a fresh CPU kernel. The run made `750` updates and selected epoch `123` using validation loss. Held-out test MSE was `0.001581` for the selected network versus `0.285793` for the training-mean baseline; test MAE was `0.030354` versus `0.503849`. The notes embed the data, learning curves, and before-and-after predictions alongside process diagrams.

For Training Problems and Solutions, all eight code cells passed in a fresh CPU kernel. Input scaling or a smaller learning rate stabilized the scalar example. On the curved diagnostic task, validation MSE was about `0.12494` for a straight line and `0.06460` for a squared-feature baseline. The selected network snapshot had validation MSE `0.052480`, versus `0.113850` for the later overfit state. Gradient, clipping, inactive-activation, and tiny-batch demonstrations also passed. These are diagnostic validation comparisons, not final test estimates.

For Build Your First Neural Network, all ten code cells passed in a fresh CPU kernel with scikit-learn `1.6.1`. The Iris project uses separate training, validation, and test groups and training-only scaling. Validation selected epoch `55`. Both logistic regression and the neural network correctly classified `28/30` test flowers (`93.3%`); test log loss was `0.2067` and `0.1403`, respectively.
